title: x402 server

The AgentTrust x402 server adds a pre-payment gate to the x402 flow. Before a payment settles, it calls `PolicyVault.gate`; only on `Allow` does it settle USDC through Monad's molandak facilitator.

## The flow

```
1. client requests a paid resource with no payment proof
2. server returns 402 with payment requirements
3. client produces a payment payload
4. verify  → molandak facilitator validates the payload
5. gate    → PolicyVault.gate(payer, payeeAgentId, amount)
                → Allow | Deny | RequireValidation
6. on Allow:              settle → molandak facilitator moves USDC
   on Deny:               402 with the deny reason
   on RequireValidation:  402 asking for a capability attestation
```

The facilitator handles payload validation and USDC settlement. AgentTrust adds only step 5 — the policy gate.

## Endpoints and addresses

| Piece | Value |
|---|---|
| Facilitator | `https://x402-facilitator.molandak.org` |
| USDC | `0x534b2f3A21130d7a60830c2Df862319e593943A3` |
| PolicyVault | `0x34b3bB1a99377128126201359749FE7614275E37` |
| RPC | `https://testnet-rpc.monad.xyz` |

## The gate call

The server resolves the payment's `payer`, the payee's ERC-8004 `payeeAgentId`, and the `amount`, then calls the gate. Using the SDK:

```ts
import { createPublicClient, http } from "viem";
import { gate } from "@monad-agenttrust-sdk/sdk";

const client = createPublicClient({
  transport: http("https://testnet-rpc.monad.xyz"),
});

const decision = await gate(client, {
  policyVault:  "0x34b3bB1a99377128126201359749FE7614275E37",
  payer,
  payeeAgentId,
  amount,
});

if (decision.kind !== "Allow") {
  // return 402 with decision.reasonName (Deny)
  // or decision.capability (RequireValidation)
  return respond402(decision);
}

// Allow — settle through the facilitator, then record the spend
await settleThroughFacilitator(/* … */);
```

After settlement, the server books the spend so the daily and velocity counters advance:

```ts
import { recordSpend } from "@monad-agenttrust-sdk/sdk";

await recordSpend(wallet, {
  policyVault: "0x34b3bB1a99377128126201359749FE7614275E37",
  payer,
  amount,
});
```

`recordSpend` runs only after the transfer actually happens, so a denied or unsettled payment never inflates the counters.

## Responses

A `Deny` returns a `402` carrying the reason ([DenyReason codes](/reference/deny-reason-codes)). A `RequireValidation` returns a `402` indicating the capability the payee must obtain ([Capability validation](/reference/capability-namespaces)).
