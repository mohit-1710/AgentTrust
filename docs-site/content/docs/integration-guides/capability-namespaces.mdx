---
title: "Configure the audit capability"
description: "Pin a conformance suite and accepted issuers without creating a general namespace system."
---

The frozen first version supports one capability: `invoice.audit.v1`. Its wire fields are `capability_namespace: "invoice.audit"` and `capability_version: 1`.

The owner configures a purchase profile with a nonzero `conformance_suite_version`, the suite hash and 1–4 unique `accepted_issuers`. The suite identifies the tests and expected schema. The evidence-manifest hash identifies a particular validation run; do not interchange them.

Then the owner registers a session for that exact profile/revision and approves the exact service identity for that profile. The worker receives only that session's restricted key. Do not give the same untrusted worker another key assigned to a weaker profile while claiming the stronger requirement is unavoidable.

When a profile changes, revoke its old session and register a fresh session ID bound to the new revision. Reusing the protocol key is allowed only after its old session is revoked.

This build has no public namespace-registration API, arbitrary capability catalog or automatic issuer discovery. A different capability is a scope change, not a string to insert into the current profile.
