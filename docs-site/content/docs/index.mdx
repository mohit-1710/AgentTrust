AgentTrust is a non-custodial pre-payment gate for AI-agent payments on Monad. Before a payment settles, it reads the payee agent's on-chain ERC-8004 reputation and the payer's spending policy, then returns one decision: `Allow`, `Deny`, or `RequireValidation`. Nothing in the flow ever takes custody of funds — AgentTrust only decides whether the payment should proceed.

ERC-8004 runs natively on Monad as three canonical registries: agent identity (`IdentityRegistry`), reputation (`ReputationRegistry`), and capability validation (`ValidationRegistry`). AgentTrust deploys one contract on top of them — `PolicyVault` — and ships an x402 server, an MCP server, and a TypeScript SDK that read those registries and enforce the gate.

npm i @monad-agenttrust-sdk/sdk
```

```

## What's deployed

AgentTrust deploys exactly one contract — `PolicyVault`. The three ERC-8004 registries and USDC already exist on Monad testnet; AgentTrust reads them.

## The pieces

**PolicyVault** is the decision contract. A single `gate(payer, payeeAgentId, amount)` call enforces a payer-chosen policy: per-transaction cap, daily cap, sliding-window velocity, a multisig kill-switch, a counterparty ERC-8004 reputation threshold (averaged over a payer-chosen set of trusted attestors), and optional capability validation. It returns `Allow`, `Deny`, or `RequireValidation`. Written in Solidity, built with Monad Foundry, covered by 20 Foundry tests.

**x402 server** wires the gate into the x402 payment flow: `verify` → `gate` → `settle`, settling through Monad's molandak facilitator with USDC.

**MCP server** exposes the gate and reputation reads to agents and assistants. Four tools: `get_reputation`, `gate_payment`, `register_agent`, `seed_feedback`.

**SDK** is the TypeScript surface (built on viem). Two calls do the work: `gate()` and `getReputation()`.

## How a payment flows

```
x402 client
     │  POST /protected  (no payment proof)
     ▼
x402 server ──verify──► molandak facilitator
     │
     │  gate(payer, payeeAgentId, amount)
     ▼
PolicyVault ──reads──► ReputationRegistry (ERC-8004)
     │                 averaged over the payer's trusted attestor set
     │
     ├─ Allow            ──settle──► USDC transfer via facilitator
     ├─ Deny             ──► 402 with the deny reason
     └─ RequireValidation ──► 402 asking for a capability attestation
```

## ERC-8004 reputation, read correctly

`PolicyVault` reads counterparty reputation from the ERC-8004 `ReputationRegistry` via `getSummary(agentId, clients[], tag1, tag2)`, which returns `(count, summaryValue, decimals)` where `summaryValue` is the **average** score across the supplied clients. The `clients` array must be non-empty — it is the payer's chosen set of trusted attestors. A policy that trusts no one trusts no reputation; trust is always explicit and payer-controlled.
