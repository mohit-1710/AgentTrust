title: "Native vault and sessions"

---

The native core keeps an owner's spendable balance separate from unused storage credit. An initial funded actor starts paused at policy revision `0`, with zero daily and dispatch limits. Configuration is an explicit owner action.

## Management methods

| Method | Purpose |
|---|---|
| `deposit(storage_credit_yocto)` | Split attached NEAR into storage credit and spendable principal; the sole actor-creation path. |
| `set_policy(...)` | Set the owner-wide daily cap, fixed-minute dispatch count and pause state. |
| `set_profile(...)` | Select a capability/suite and accepted issuers, or explicitly select no requirement. |
| `register_session(...)` | Bind a new session ID and actual native public key to one profile/revision, expiry and purchase cap. |
| `revoke_session(session_id)` | Prevent new admissions under that session. |

Management requires `predecessor_account_id == signer_account_id`, derives authority from that direct caller and requires exactly one yoctoNEAR attached deposit. Funding is the payable exception. The worker's protocol key cannot attach management deposits and must have only the singleton method allowlist `execute_payment`.

## Session rules

A session ID is immutable. Changing key, profile or expiry means revoking the old session and registering a new ID. At most one unrevoked session may use a key for an owner. A profile edit changes its revision and makes old-revision sessions unusable for a new purchase until explicitly rebound. Owner authorization changes advance policy revision without resetting money counters.

Profile IDs are nonempty, at most 64 UTF-8 bytes, with no normalization. The prototype retains at most 4 profiles and 8 sessions; revoked sessions do not free their IDs.

No full-access owner/deploy key belongs in the worker, MCP environment or browser bundle. See [pause and revocation](/programs/policy-vault/kill-switch-policy) and [explicit service lists](/programs/policy-vault/service-trust).
