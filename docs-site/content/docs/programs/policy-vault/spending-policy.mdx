> This page describes the frozen native design. Check [implementation status](/reference/changelog) before using an integration; a planned interface is not a deployed service.

The sole payment asset is native `NEAR`. One NEAR equals `10^24` yoctoNEAR. JSON amounts are unsigned decimal strings; neither the contract nor client converts money through a JavaScript floating-point number.

## Owner-wide daily limit

For a new payment, daily usage is:

```text
settled amounts dispatched in the current UTC day
+ all unresolved payment reservations, including earlier days
+ the proposed amount
```

That sum must not exceed the owner's cap. The exact cap is allowed; one yoctoNEAR more is denied. Each session also has a per-purchase cap. All sessions share the owner-wide counters.

The original dispatch day stays with each payment. Successful settlement moves its reservation into that day's settled bucket; a definitive transfer failure restores the owner's available claim once. Failure still consumes a dispatched attempt. Midnight and policy edits cannot erase unresolved exposure.

## Storage and available funds

`deposit(storage_credit_yocto)` splits attached funds before pricing an actor's initial record. Record growth is charged to that actor's storage credit, not to spendable principal or another tenant. Management's one-yocto deposits are not credited as spendable funds. This prototype does not refund previously charged credit when a record shrinks.

Before an outflow, the actual contract balance must cover conservative post-operation storage, operating/nonspendable liabilities, unused storage credits and all available claims. Do not subtract already-dispatched pending principal a second time from the runtime balance. Actual serialization, promise deduction and refund timing require runtime evidence.

A pending or unknown outcome is never refundable merely because time passed. Withdrawal is designed to send only the owner's available principal to that same owner, using the same asynchronous discipline.

Demonstration settings in the plan are 1 NEAR funding, 0.01 NEAR purchase cap and 0.05 NEAR daily cap. They are example settings, not production recommendations or dollar limits.
