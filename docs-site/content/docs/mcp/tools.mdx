> These are the implemented local input schemas. Their protocol tests use mock RPC; native execution is a separate gate.

| Tool | Input | Result |
|---|---|---|
| `list_services` | Optional `cursor`, optional `limit` from 1–20 | Registered page, configured-origin label and eligibility `not_evaluated`. |
| `get_service` | `serviceId` | Current registered identity/version or `null`. |
| `get_policy` | Empty object | Fixed owner's policy, exact service permissions and blocks, or `null`. |
| `preview_payment` | Signed `quote`, `credential` reference or `null` | Decision with signer authorization explicitly unproven. |
| `pay_service` | `serviceId`, `csvUtf8`, `paymentId` | Paid report, typed denial, failed payment, uncertainty or retrieval failure. |
| `get_payment` | `paymentId` | Final-block settled/failed observation or explicit uncertainty. |

All schemas reject unknown fields. `paymentId` is canonical base64 for 32 bytes and CSV is limited to 64 KiB of valid UTF-8. `pay_service` does not accept an arbitrary URL, local file path, raw transaction or instruction to sign arbitrary bytes. The SDK supplies the fixed native flow and validates the catalog commitment.

The same payment ID must be preserved through retries for that attempt. If the outcome is unresolved, the agent must stop replacement purchases. Switching suppliers after a definitive non-dispatch rejection is a separate, deliberately identified attempt.

A preview refusal has origin `preview`; it does not include a rejection transaction. A real rejected call has origin `executed_rejection`. Reusing a journaled preview refusal has origin `recorded_replay` and retains its original preview origin. A dated demonstration capture must also be labeled as a replay when shown later. Only admitted operations appear in contract payment history.

Tool results contain `structuredContent: { result }` and matching JSON text. A typed refusal is a normal result. Read failures are distinct from absent data; generic payment exceptions return sanitized uncertainty with the original ID. Pending, missing, uncertain or `retrieval_failed` never means unpaid. Inspect the original attempt; do not switch suppliers or create a replacement ID from those states.
