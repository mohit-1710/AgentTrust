> This page describes the frozen native design. Check [implementation status](/reference/changelog) before using an integration; a planned interface is not a deployed service.

| Tool | Intended behavior |
|---|---|
| `list_services` | Distinguish registered services, configured origins and preview eligibility. |
| `get_service` | Read the exact registered identity/version and related service facts. |
| `get_policy` | Read the configured owner's policy and session context. |
| `preview_payment` | Explain current policy without proving key possession or reserving funds. |
| `pay_service` | Buy from a configured service using explicit CSV content and a caller-supplied stable payment ID. |
| `get_payment` | Inspect an existing operation's immutable context and current state. |

`pay_service` accepts service ID, CSV content and payment ID. It does not accept an arbitrary URL, local file path, raw transaction or instruction to sign arbitrary bytes. The SDK supplies the fixed native flow and validates the catalog commitment.

The same payment ID must be preserved through retries for that attempt. If the outcome is unresolved, the agent must stop replacement purchases. Switching suppliers after a definitive non-dispatch rejection is a separate, deliberately identified attempt.

A preview refusal has origin `preview`; it does not include a fabricated rejection transaction. A real rejected call has origin `executed_rejection`. A saved demonstration is `recorded_replay`, with capture time. Only dispatched operations appear in payment history.

The final input/output schemas and executable transport checks are T19 work. This table fixes scope without adding owner-management, issuance, hosted-signing, resources or prompt tools.
