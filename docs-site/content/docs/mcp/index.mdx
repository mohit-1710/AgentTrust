> The local implementation and mock-RPC stdio checks have passed. Native worker authorization and settlement remain separate runtime gates; see [implementation status](/reference/changelog).

The MCP surface is local stdio with six tools, using the pinned official MCP SDK. `pay_service` is the only money-moving tool. The other tools inspect services, policy, previews and payment state.

The worker process holds only its restricted key, pinned owner/session and network/core configuration. Owner management and issuer operations run separately. There is no hosted signer, shared full-access key or generic `sign` tool.

Service discovery is bounded to registered records and the configured version-to-origin catalog. Being listed, having a configured endpoint and passing a policy preview are different facts.

The compiled server has been exercised through an actual stdio client against loopback mock RPC. Its retry integration uses the real SDK journal with chain methods doubled. These local transport and recovery checks are separate from native payment evidence. The [r2 testnet capture](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r2-evidence.md) records a scripted MCP buyer; fresh [r3](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r3-evidence.md) and [r4](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r4-evidence.md) records each show five local-model responses using the bounded MCP flow and a settled 0.002 NEAR purchase. The host exposed only the current allowed supplier and supplied the precommitted payment ID/CSV. No package release or hosted MCP endpoint is claimed.
