> This page describes the frozen native design. Check [implementation status](/reference/changelog) before using an integration; a planned interface is not a deployed service.

The demonstration should establish this complete chain of evidence:

```text
registered service identity/version
  -> fresh endpoint challenge + pinned public fixture suite
  -> issuer-authenticated scoped credential
  -> owner-selected profile and exact service approval
  -> signed quote for the exact CSV
  -> authoritative native admission and final settled record
  -> actual report bound to the original input
```

A later credential revocation or changed payout identity must block a **fresh** purchase. An exact retry of an already-dispatched invoice must return its original state rather than pay again. These are distinct cases with distinct operation IDs where appropriate.

The conformance endpoint accepts only committed public fixtures. It does not certify all future behavior or expose arbitrary paid input for free. The issuer and two providers are controlled demonstration components.

Required evidence includes the service/version, suite and run-evidence hashes, credential reference, owner policy/profile revisions, invoice/request hashes, actual transaction/receipt IDs, final payment state and checked output. No result is asserted here until that bundle exists and has been inspected.
