title: "Verification"
description: "Each claim needs evidence from the lane that can establish it."
---

| Lane | Establishes | Does not establish |
|---|---|---|
| Pure Rust | Canonical values, policy/arithmetic and ordinary-value transitions. | Actual native access-key or receipt behavior. |
| Pure TypeScript/HTTP | Byte agreement, parsing, schemas, request/receipt binding and retry logic. | An actual chain payout. |
| WASM build | Target compilation and required host imports/exports. | Contract execution or safe custody. |
| UI/docs | Rendering, truthful data/copy and active corpus correctness. | Payment settlement. |
| Native runtime | Real key restrictions, storage/balance behavior and receipt/callback ordering. | A publicly hosted complete product by itself. |
| Live task | Actual configured service purchase, final state and checked useful output. | General service quality or production security. |

Current results live in [implementation status](/reference/changelog) and the sprint ledger. No historical proof badge or fixture screenshot is treated as a native run.

The standing rules make database-writing Sandbox execution user-run. Default local tests and builds must not launch it, deploy, fund accounts or pay. A prepared harness and a passing compilation do not satisfy a runtime gate.

The final demo must include actual supplier refusal, successful native purchase, useful output, identity/credential changes blocking a fresh attempt and exact retry without another payout. Controlled providers, the project-operated issuer and any recorded playback must be disclosed.
