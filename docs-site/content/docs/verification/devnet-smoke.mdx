title: "Runtime and testnet runs"
description: "Prepare reproducible evidence without turning default checks into live operations."
---

Native runtime and live testnet runs are separate from `pnpm check:fast` and the WASM build. A local runtime can establish host semantics; an actual testnet purchase must also establish the configured network/core, service identity and useful output.

`verify:runtime` is the user-run Sandbox harness, and `evidence:check` validates supplied evidence. Accepted [native captures](https://github.com/mohit-1710/AgentTrust/blob/main/docs/native-runtime-evidence.md) support 20 of 21 case groups; the refund-gap case keeps the full gate incomplete. The explicit testnet commands produced an [r2 scripted qualification](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r2-evidence.md) and two fresh local-model operator rehearsals, [r3](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r3-evidence.md) and [r4](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r4-evidence.md). Each fresh run records a separate settled 0.002 NEAR model-requested purchase, direct contract refusals and an exact native retry. Follow the [testnet runbook](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-demo-runbook.md) and inspect each dated capture with `demo:evidence:check`.

`pnpm check:runtime:compile` checks harness compilation without starting Sandbox. Compilation and evidence-schema checks do not prove a host scenario. See the [runtime runbook](https://github.com/mohit-1710/AgentTrust/blob/main/docs/runtime-runbook.md) for the exact user-run command and still-missing matrix coverage.

Before running an accepted harness, read its exact effects and runbook. Sandbox persists database state and remains user-run under the standing restriction. Account/key creation, funding, deployment, payments and public hosting need their own authorized execution step. Never put these operations in default install hooks or unrelated CI checks.

The evidence must retain raw public RPC results and final receipt outcomes, not just a transaction hash or a wrapper's success flag. Verify the core code hash and actual final payment state. State, balance and receipt observations must identify their block/finality context.

Use synthetic inputs. Record public role/account/key fingerprints only; do not capture private keys, environment dumps or user CSV into a public artifact.
