The [r2 testnet evidence](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r2-evidence.md) records two settled native payments, three executed contract refusals, an exact retry and a scripted MCP buyer. Its [public RPC extract](https://github.com/mohit-1710/AgentTrust/blob/main/docs/evidence/r2-native/README.md) exposes selected direct transaction and receipt fields. Fresh [r3](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r3-evidence.md) and [r4](https://github.com/mohit-1710/AgentTrust/blob/main/docs/testnet-r4-evidence.md) operator rehearsals each check 23 captures/218 artifact hashes and record five local Ollama model responses, A's read-only `MISSING` preview, a host-allowed B request, a separate settled 0.002 NEAR purchase, direct executed refusals, exact retry and keyless replay. The model did not set the payment ID or CSV. [Native Sandbox evidence](https://github.com/mohit-1710/AgentTrust/blob/main/docs/native-runtime-evidence.md) supports 20 of 21 case groups; the refund-gap case is unobserved. The public website feed exposes dated on-chain decisions; model, MCP and providers remain local.

Every runtime/demo record should contain:

| Category | Required fields |
|---|---|
| Build | Git commit, tool/dependency versions, normal or fault-injected artifact, deployed code hash. |
| Context | UTC capture time, actual network/core and actor roles/public key fingerprints. |
| Operation | Stable payment ID, invoice hash, amount/asset, request hash and credential reference. |
| Chain | Actual transaction ID, relevant receipt IDs/outcomes, final contract state and finality context. |
| Output | Returned report, output hash, check result and its bounded meaning. |
| Verification | Command, exit status, expected assertions, actual results and remaining limitations. |

Evidence statuses distinguish `passed`, `failed`, `not_run`, `user_run_required`, `recorded_replay` and `unavailable`. Reading an old bundle does not create a new live run.

Decision origin is equally explicit: `preview` has no signing-key proof or invented transaction; `executed_rejection` links an actual rejected call; `recorded_replay` shows its capture time. Only dispatched operations appear in payment history.

Core authorization, payout, settlement and replay protection must be real in the final demonstration. Synthetic datasets and controlled suppliers/issuer are disclosed. A scripted buyer harness is labeled as scripted; an actual agent trace must show real tool calls using the same bounded interfaces.
