AgentTrust is one deployed contract — `PolicyVault` — plus a set of off-chain services (an x402 server, an MCP server, a TypeScript SDK) that read the three canonical ERC-8004 registries on Monad and enforce a pre-payment gate. This page is the wiring.

## Composition diagram

```
┌──────────────────────────────────────────────────────────────┐
│  x402 server                                                   │
│   verify ─► gate ─► settle                                     │
│   settlement runs through the molandak x402 facilitator + USDC │
└───────────────────────────────┬──────────────────────────────┘
                                 │  gate(payer, payeeAgentId, amount)
                                 ▼
                ┌──────────────────────────────────┐
                │  PolicyVault  (deployed contract) │
                │  ├─ per-tx cap                    │
                │  ├─ daily cap                     │
                │  ├─ sliding-window velocity       │
                │  ├─ multisig kill-switch          │
                │  ├─ counterparty reputation       │
                │  └─ optional capability check     │
                └───────────────┬──────────────────┘
                                │  reads
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ IdentityRegistry │ │ReputationRegistry│ │ValidationRegistry│
│   (ERC-8004)     │ │   (ERC-8004)     │ │   (ERC-8004)     │
└──────────────────┘ └──────────────────┘ └──────────────────┘
```

AgentTrust deploys only `PolicyVault`. The three ERC-8004 registries are canonical contracts that already exist on Monad testnet; AgentTrust reads them and never redeploys them.

## PolicyVault — the decision contract

`gate(payer, payeeAgentId, amount)` returns one of three decisions:

| Decision | Meaning |
|---|---|
| `Allow` | Every active check passed. Settle the payment. |
| `Deny` | A check failed. The reason is surfaced to the caller. |
| `RequireValidation` | The policy requires a capability attestation the payee does not yet have. |

The checks `gate` enforces, in order:

| Check | What it does |
|---|---|
| Kill-switch | A multisig-controlled emergency stop. If engaged, every payment denies. |
| Per-transaction cap | Denies if `amount` exceeds the policy's per-tx limit. |
| Daily cap | Denies if today's cumulative spend plus `amount` exceeds the daily limit. |
| Sliding-window velocity | Denies if spend within the rolling window plus `amount` exceeds the window cap. |
| Counterparty reputation | Reads the payee's averaged ERC-8004 reputation and denies if it falls below the policy threshold. |
| Capability validation | If the policy requires a capability, returns `RequireValidation` unless a matching attestation exists. |

Contract interface, configuration calls, and spend accounting: [PolicyVault](/programs/policy-vault).

## Reading ERC-8004 reputation

`PolicyVault` reads the counterparty's reputation from the ERC-8004 `ReputationRegistry`:

```solidity
(uint256 count, uint256 summaryValue, uint8 decimals) =
    reputationRegistry.getSummary(payeeAgentId, clients, tag1, tag2);
```

`summaryValue` is the **average** score across the `clients` array. That array is the payer's chosen set of trusted attestors — it must be non-empty. The policy compares `summaryValue` against its configured minimum threshold. There is no global reputation: trust is always scoped to the attestor set the payer decided to honor.

Identity is resolved through `IdentityRegistry` (which agent an ID maps to); capability attestations come from `ValidationRegistry` (used only when a policy enables the capability check).

## The off-chain surfaces

| Surface | Role |
|---|---|
| x402 server | Implements the x402 `verify → gate → settle` flow. Calls `PolicyVault.gate`, and on `Allow` settles USDC through the molandak facilitator. |
| MCP server | Exposes `get_reputation`, `gate_payment`, `register_agent`, `seed_feedback` to MCP clients. |
| SDK (`@monad-agenttrust-sdk/sdk`) | viem-based TypeScript helpers — `gate()` and `getReputation()`. |

## The x402 flow

```
1. client requests a paid resource with no payment proof
2. x402 server returns 402 with payment requirements
3. client produces a payment payload
4. x402 server: verify  → molandak facilitator validates the payload
5. x402 server: gate    → PolicyVault.gate(payer, payeeAgentId, amount)
                          → Allow | Deny | RequireValidation
6. on Allow: settle      → molandak facilitator moves USDC
   on Deny / RequireValidation: 402 with the reason
```
