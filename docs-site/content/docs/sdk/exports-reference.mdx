These functions are implemented in the local native workspace package:

| Export | Result |
|---|---|
| `encodeInvoice(invoice)` | Canonical domain-prefixed Borsh bytes. |
| `invoiceHash(invoice)` | SHA-256 of those bytes, as a base64 Hash32. |
| `encodeIdentityDescriptor(descriptor)` | Bytes in the separate descriptor domain. |
| `identityDescriptorHash(descriptor)` | Descriptor SHA-256 as base64. |
| `requestHash(csvUtf8)` | Hash of the request domain plus exact bounded UTF-8 CSV bytes. |
| `verifyInvoiceSignature(quote, registeredPublicKey)` | Boolean cryptographic verification against the supplied registry key. |
| `verifyIdentityDescriptorSignature(descriptor, signature, registeredPublicKey)` | Boolean descriptor verification against the supplied registry key. |

Encoders reject malformed fields, unknown keys, incorrect binary lengths, invalid account IDs and lossy Unicode conversion. Money/timestamps never go through `Number`. Signature helpers return false for malformed or invalid signatures.

A valid signature proves only the signed bytes. These helpers do not establish current policy, session authority, dates, endpoint ownership, registry version, capability status or settlement. The descriptor's embedded invoice key is not selected as a trust root.

Shared fixture keys are public test material. Never use or fund them as real accounts or merchant keys. Rust and TypeScript fixtures prove local byte agreement; equivalence with the native host's execution still needs runtime verification.

The main entrypoint also exports `AgentTrustClient`, `ServiceDirectory`, endpoint commitment helpers and finality validators. `AgentTrustOwner` is available only from the separate `/owner` entrypoint. These local implementations are not published npm packages. MCP and the paid HTTP flow remain under implementation.
