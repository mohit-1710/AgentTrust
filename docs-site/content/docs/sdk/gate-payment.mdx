> This page describes the frozen native design. Check [implementation status](/reference/changelog) before using an integration; a planned interface is not a deployed service.

The frozen client surface is:

```ts
previewPayment(args: ExecutePaymentArgs): Promise<PreviewResult>;
executePayment(args: ExecutePaymentArgs): Promise<ExecutionResult>;
getPayment(ownerId: AccountId, paymentId: Hash32): Promise<PaymentView | null>;
awaitPayment(ownerId: AccountId, paymentId: Hash32, timeoutMs: number): Promise<PaymentObservation>;
payService(args: {serviceId: AccountId; csvUtf8: string; paymentId: Hash32}): Promise<PaidAuditResult>;
```

These are interface contracts, not a claim that every integration method is implemented in this snapshot.

A preview declares `authorization: "not_proven_by_view"`. It cannot prove possession of a worker key or reserve capacity. The write method checks the actual signer/key and current state.

Before broadcast, `payService` must durably save the exact signed quote and immutable attempt context in a private local JSON file. The journal contains no private key or CSV content. Failure to persist it stops submission; a conflicting saved ID is never overwritten.

On timeout or restart, load the same attempt and query its original ID. Not-found after an uncertain broadcast is not proof that it cannot execute later. Observe or rebroadcast only the identical quote/ID; do not silently requote, switch providers or generate a replacement ID.

Before resuming or retrieving output, compare owner, network/core, service, invoice hash and request hash with the caller's operation. A settled original receipt remains redeemable after invoice expiry. A definitively rejected/failed attempt can be reported so the caller deliberately starts a new attempt; an unknown one cannot.
