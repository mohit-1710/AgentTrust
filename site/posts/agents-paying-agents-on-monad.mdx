## The trillion-dollar trust gap

Stripe moves close to a trillion dollars a year between humans. KYC checks, fraud teams, ML scoring, chargeback flows, regulatory filings. None of that scaffolding exists for agents. The hosted-MCP wave from Anthropic, OpenAI, and every framework around them ships a signer to the operator. That is a security model dressed up as DX. The operator owns every contract record every user creates and the user has no recourse if the operator's signer is compromised or rotated without notice.

Agent payments are different from human payments in one structural way. There is no human in the loop to escalate to. A confused human can pause and call their bank. A confused agent fires the transaction and moves on to the next prompt. The decision has to be settled before the bytes leave the host. Async review does not work when the agent has already paid and the API has already returned the gated resource.

Prompt-time guardrails do not survive contact with adversarial input. A jailbreak, a tool-poisoning attack, a context that smuggles a payment instruction past the system prompt, an MCP server that returns a malicious description on its second call. All of these route around the agent's reasoning surface. The chain is the only surface where the rules cannot be argued with. A policy that lives in a contract record, signed by an authority you control, cannot be talked out of refusing a payment.

## What a trust layer needs

Three orthogonal axes. Identity is who is signing. Reputation is what they have done before and how it went. Capability is whether they are authorized to receive this specific kind of payment. These are the three legs of ERC-8004, the emerging trust standard for autonomous agents.

Identity, Reputation, and Validation all live natively on Monad as canonical ERC-8004 contracts with stable addresses. AgentTrust reads all three from a single gate contract, PolicyVault, and binds the decision into the payment path with a typed SDK, an MCP server, and 20 Foundry tests over the gate.

The three legs are independent. An agent can have a strong identity and zero reputation. A long reputation history and a fresh capability claim. The trust layer composes them at gate time, not at registration time. A payment is gated by the policy the payer set, against the counterparty's live on-chain state, before any value moves. The gate reads all three registries in a single `gate(payer, payeeAgentId, amount)` call, so the decision is settled before the x402 server settles the transfer.

Composing means PolicyVault evaluates the active checks against the counterparty's identity, the counterparty's ERC-8004 reputation averaged over the payer's trusted-attestor set, and any required validation attestation. If every active check passes, the gate returns `Allow`. If any check fails, the gate returns `Deny` with a reason code an integrator can route on, or `RequireValidation` when a capability attestation is missing.

## Why Monad

Two reasons. First, ERC-8004 lives natively on Monad. Identity, reputation, and validation are canonical contracts, so reading identity plus reputation plus validation into one gate decision is straightforward. AgentTrust ships exactly that. A single `init_policy` call configures a fresh wallet to a fully functional agent identity in one signature. Read [/blog/bootstrap-an-agent-in-one-tx](/blog/bootstrap-an-agent-in-one-tx) for the trace.

Second, the x402 facilitator from molandak runs on Monad testnet. AgentTrust ships an x402 server that runs the gate inline in its verify, gate, settle flow. The settlement rail and the trust layer arrive together. Anyone building agent payments on Monad can wire the SDK in a few lines, point it at the facilitator, and gate every `/verify` call against an on-chain policy the payer set.

The combination is what makes the bet specific. Monad runs ERC-8004 natively and has a live x402 rail through the molandak facilitator. AgentTrust binds the chain-level trust primitives to the rail that moves stablecoins. The gate returns its decision before the transfer settles. No off-chain coordinator. No multi-step retry script. No operator-owned signer.

## What's live today

PolicyVault, the one contract we deployed on Monad testnet, plus the three canonical ERC-8004 registries it reads. PolicyVault is the decision engine. It composes per-tx and daily caps, sliding-window velocity, a multisig kill-switch, a counterparty reputation threshold averaged over the payer's trusted-attestor set, and optional capability validation. The x402 server runs the gate inline in its verify, gate, settle flow against the molandak facilitator and native USDC.

The SDK is on npm at `@monad-agenttrust-sdk/sdk`. The MCP server `agenttrust` exposes get_reputation, gate_payment, register_agent, and seed_feedback, so agents can use it from Claude Code. Your key stays on your machine and you own every contract record you create. The 20 Foundry tests cover the gate. Read [/blog/inside-the-policyvault-gate](/blog/inside-the-policyvault-gate) for what they check.

The demo runs a live x402 round-trip on Monad testnet. A test client agent calls a gated endpoint, the facilitator hits `/verify` against the AgentTrust gate, the gate evaluates the policy, returns the decision, and the round-trip lands a settled transaction on Explorer. Agent 1763 gets ALLOW, scammer 1764 gets DENY, and an unknown counterparty gets REQUIRE_VALIDATION, all real on-chain. The code is open and the contract addresses are public, so any reader can verify the trace from their own machine.

## What's next

More facilitator adapters land next, alongside whatever x402 entrant ships after them. The shape of each adapter is small. About 150 lines, one config object, one `/verify` shim that maps the facilitator's payload onto the gate input. A wallet relay for hosted writes is on the roadmap so cloud agents can sign without ceding identity to the operator.

Validation coverage expands next. KYC, AML, and capability claims that integrators downstream-filter via per-policy trusted-attestor sets. The ERC-8004 ValidationRegistry is open. Anyone can register as an attestor. Integrators choose which attestors they trust per policy, and the gate enforces the choice on chain.
